# 创作工具箱：人物、剧情、状态记忆、质量门槛

> 本分册补齐"写长篇最容易崩的四件事"：**人物写到后期失真、伏笔埋了不收、状态记不住、章章都在及格线下**。
> 使用者：开书设定期（人物架构、剧情引擎）+ 逐章写作期（状态回写）+ 每章交付前（质量门槛）。

---

## 一、人物工程

### 1.1 人物档案卡（主要角色每人一张）

| 字段 | 说明 |
|---|---|
| 欲望 | 他**要什么**（具体、可被看见） |
| 恐惧 | 他**怕什么**（决定他在压力下的选择） |
| 动机 | 为什么是现在（时间压力） |
| 言行约束 | 他的说话习惯、口头禅、**绝不会做**的事 |
| 内外反差 | 外在形象 vs 内在真实（戏就在反差里） |
| 需求(need) | 他**真正**需要的（往往自己不知道，与"欲望"错位才出戏） |

> **驱动力三角**（欲望 want / 需求 need / 恐惧 fear）：三者张力越大角色越立得住。欲望是表面目标，需求是深层成长，恐惧决定压力下的两难选择——三者缺一，角色容易"想干嘛就干嘛"没有代价。
> **角色弧线**（主角必填）：起点信念 → 经历的关键转折 → 终点信念是否位移。弧线不必都变好，但必须有变化，否则人物一条直线（后期失真，正是 §1.2 逐章情绪弧线要防的）。

### 1.2 逐章情绪弧线（防"人物一条直线"）

写法：每章记录出场角色的**起点情绪 → 终点情绪**。若连续三章同一角色"起点=终点"，就要给他一次波动。

### 1.3 认知边界表（★ 长篇最易翻车处）

**定义**：每个角色在**当前时点**知道什么、不知道什么。

| 角色 | 此刻知道 | 此刻不知道 | 通过什么渠道知道 |
|---|---|---|---|
| 主角 | …… | …… | 亲眼见／被告知／推得出 |

**写前必查**：本章每句"信息性台词"，说话人此时有没有渠道知道？
**三种渠道皆无 = 越界**，必须改成"猜测／听说的／沉默"。
> 越界的典型症状：角色说出了只有读者才知道的事；配角忽然点破主角没说过的秘密。

## 二、剧情工程

### 2.1 章末钩子五型（轮换使用，防同质化）

| 型 | 例 |
|---|---|
| 信息型 | 他查到一件不该查到的事 |
| 抉择型 | 两条路，他必须选一条 |
| 代价型 | 他做成了，但付出了什么 |
| 悬念型 | 有人来过，东西被动过 |
| 情绪型 | 一句没说完的话 |

**排布纪律**：同类钩子不连用；**悬疑不连超三章**必须有释放。

### 2.2 伏笔登记表（★ 埋了必须收）

建议文件：`005 章纲\伏笔登记表.md`

| # | 伏笔内容 | 埋设章 | 计划回收章 | 状态 | 最近提及 |
|---|---|---|---|---|---|
| 1 | …… | 第 2 章 | 第 41 章 | 未收 | 第 30 章 |

**陈旧度预警**（写入正文前逐条检查）：
- **正常**：埋设至今 ≤10 章且期间有提及
- **偏旧**：10~20 章未提及 → 建议本章提一句
- **危险**：>20 章未提及（读者已遗忘）→ 安排回收或确认弃用除名

## 三、状态记忆（跨会话不崩）

### 3.1 状态文件（truth-files）

记录**当前事实**（不是历史）：
- 世界观现状：人物在哪、势力格局
- 角色状态：谁死了、谁受伤、谁知道了什么
- 进行中的事：未完成的目标、已答应的承诺

**规则**：每章定稿后，把本章产生的**新事实**回写进去。下次开写前**先读它**，再读上一章。

### 3.2 快照与回滚

- 每 N 章（或每次大改前）打一次快照：`009 其他\版本\快照-第N章-日期\`
- 改稿前必须先快照——这是**唯一能后悔的机会**

### 3.3 断点续写（新会话启动顺序）

1. 读进度卡 → 现在到哪一步
2. 读总结章纲 → 已经写到哪
3. 读状态文件 → 当前局势
4. 读最近一次自查报告 → 有哪些未解决项
5. **向作者报告断点，再动笔**

## 四、质量门槛（每章交付前逐项核对）

### 4.1 九维门槛

| 维度 | 门槛 |
|---|---|
| 开篇钩子 | 前三段内出现危险、羞辱、损失或谜题 |
| 人物欲望 | 主角本章马上想要一个**看得见**的东西 |
| 冲突升级 | 至少三次变难，不靠流水账 |
| 对白张力 | 对白里有威胁、试探、隐瞒或交换 |
| 画面感 | 用物件、动作、场景承载信息 |
| 反转/悬念 | 前文细节在后文换意义 |
| 结尾余味 | 解决当下问题，同时留下回响 |
| 去 AI 味 | `anti-ai-rules.md` 的 T1 全过 |
| 开篇语义清晰 | 钩子不让读者误判题材或基本事实 |

### 4.2 lint 四级（机械检查层）

| 级别 | 处理 |
|---|---|
| error | 必改（T1 禁用词、升华结尾） |
| warn | 逐条裁决（结合上下文与误杀防护） |
| report | 仅记录（风格偏好） |
| suppressed | 白名单豁免，仅统计 |

**退出码约定**：0 = 无 error；非 0 = 存在 error，**禁止放行**。

### 4.3 校验修复闭环

```
字数检查 → 一致性检查 → 认知边界审查 → 去 AI 味 lint
→ 不合格：退回改（上限 3 轮）→ 3 轮未过：交给作者裁决
```

## 五、上下文包协议（防上下文爆炸）

写正文前，**只**注入这五样：

1. 本章章纲与写作要求
2. 出场角色的档案卡 + **认知边界表当前版**
3. **近章摘要**（默认最近 8 章，每章 ≤200 字）
4. **最近 1~2 章正文节选**（总量 ≤12000 字）
5. 相关伏笔条目与世界观片段

**禁止**把整本已写正文塞进上下文；需要更早细节时**按关键词检索文件**再注入片段。

> 并行写作（多子代理同时写不同章）时，本协议尤其重要：子代理看不到彼此的产出，只能靠这里给的摘要对齐。
> **同时必须额外给一份"结构化细节表"**：人物习惯动作、物件位置、口头禅——这些靠摘要传递不了，必须显式写死。

## 六、每章标准作业顺序（把上面的东西串起来）

```
① 查状态文件 + 认知边界表（我该写什么、角色知道什么）
② 填写作要求（本章目标／爽点／钩子类型／人物变化／禁写事项／字数）
③ 组装上下文包（见五）
④ 写初稿 → ⑤ 跑 lint_prose.py（error 必须清零）
⑥ 补描写（神态/环境不达标就补，见 anti-ai-rules.md 基线）
⑦ 认知边界复查 → ⑧ 伏笔登记回写 → ⑨ 状态文件回写 → ⑩ 快照
```
