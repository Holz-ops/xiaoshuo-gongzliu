# 去 AI 味：六门、三级禁用表、五律与裁决

> 本分册定义"文本读起来像不像人写的"的判定与清除规则。
> 使用者：润色去味环节（第 ⑥ 步复查）、以及**写正文时就要守**（写时即守比事后清更省）。
> 配套脚本：`scripts/lint_prose.py`（可自动查 4 门；另 2 门需人工/AI 判断）

---

## 一、三条硬边界（优先于一切去味规则）

1. **信息守恒**——不新增原文没有的事实、数字、名字、日期、因果、动机；不删限定与让步（把"可能提升"改成"提升"是篡改语气，不是去味）
2. **最小改动**——只改命中处为解决问题所必需的部分，不顺便润色
3. **结构不动**——段落顺序与数量、场景分隔位置全部保留

**一句话：宁可留一点 AI 味，不可造一个假事实。**

---

## 二、六门检测

| 门 | 检测内容 | 谁查 | 门槛 |
|---|---|---|---|
| **A 禁用词** | 三级禁用表（见三） | 脚本 | T1 = 0 容忍 |
| **B 句式套路** | "不是A而是B"、"带着一丝……"、"当……的时候" | 脚本+人工 | ≤1.0/千字 |
| **C 心理描写** | 直述式心理（他感到／心中涌起／内心翻腾） | 脚本 | 0 容忍 |
| **D 节奏** | 连续排比、长句超载、段落过密 | 脚本 | 报警线 |
| **E 对话** | 对话太完整、标签过度、连续 ≥4 句纯对话 | **人工/AI** | 每章 ≤2 处 |
| **F 结尾** | 升华总结（"他终于明白了……""这就是……的意义"） | 脚本 | 0 容忍 |

---

## 三、三级禁用表

| 级别 | 类别 | 示例 |
|---|---|---|
| **T1**<br>出现即改 | 面部套话 | 嘴角勾起／笑意不达眼底／眼底闪过一抹 |
| | 手部套话 | 指节发白／指甲陷入肉里／手不自觉地 |
| | 呼吸套话 | 心脏漏跳一拍／脊背发凉／倒吸一口凉气 |
| | 万能占位 | "有什么东西碎了"／"某种说不清的东西"（**不含**"不知为何"——它已降 T2，见下） |
| | 升华结尾 | 他终于明白了／这就是……的意义／从这一刻起 |
| | 上帝腔 | 而他不知道的是／殊不知 |
| | 情感直述 | 他很害怕／心中涌起／内心充满 —— **"很"等程度副词不可省**：判的是"直述情感"，不是"情绪修饰动作"。「他紧张得手心出汗」「他愤怒地捶了一下墙」是白描，**不算**，脚本已按此收紧 |
| **T2**<br>同段聚集才处理 | 依赖句式 | "很X很Y但确实Z"／"连他自己都没察觉" |
| | 高频比喻 | 像溺水的人抓住浮木 |
| | 程度副词 | 非常／十分／极其／格外／异常 |
| | **"他知道"** | ⚠️ **必须人工过一眼**：中文小说里「他知道 + 具体判断」是**正常写法**（"他知道等着是什么意思""差的八百块，他知道去哪挣"）；只有**升华式**（"他知道，从这一刻起一切都不同了"）才要改 |
| | **"不知为何"** | ⚠️ **必须人工过一眼**（与"他知道"同款处置）：AI 味确实存在，但"不知为何，他心里一紧"也是中文网文的正常起句。**曾误列 T1（脚本比本文档更宽），2026-10-17 降为 T2** |
| **T3**<br>全文密度控制 | 意象密度 | 冷感意象、水/液体意象滥用 |
| | 景物同步 | 景物强制同步情绪（"风也停了他的心也凉了"） |

## 四、五律（写作与改写共同遵守）

1. **破折号**：正文中每章 ≤3 处（独立成行的场景分隔符不计）
2. **心理必须落成"一个动作 + 一个物件"**
3. **删"而他不知道的是"式上帝腔**
4. **比喻要么有画面，要么删**
5. **重复时换质感，不换同义词**

---

## 五、七处裁决（规则冲突时按此执行）

| 冲突 | 裁决 |
|---|---|
| 毛边／参差感 | 实测人机无差别；不为制造参差调句长，也不把原本参差的改齐 |
| 排比 | 句内同构排比留；相邻句复用同一句法骨架，改 |
| 被动句 | 被动本身不改；只在"该追责而被动句藏起责任人"时改 |
| 抽象换物象 | 自己的稿：标缺口向作者要料；成稿清理：只把已有具体值提到概括词位置 |
| 破折号 | 该删（AI 频率远高于人）；作者惯用且功能明确时以作者习惯为准 |
| 段首"值得注意的是" | 清理模式补"这"字；创作模式整句删 |
| 句首"其实" | 独立成分删；句中承担转折的留 |

## 六、误杀防护（豁免不改）

- **角色化表达**：口头禅、方言腔、职业用语
- **对话特例**：人物刻意伪装的书面腔
- **功能型标点**：表音量渐弱的省略号
- **有力短句**：不为检测器牺牲表达力

**门槛校准原则**：密度型门槛 = **多部人类创作文本的密度上限 × 1.25**——"人类作者也会用到的量，超过才报"。
**报警线不是删除线**：超线先判断是硬伤还是风格，再决定改不改。

## 七、脚本用法

```bash
python scripts/lint_prose.py <md目录> --top 10 --json <输出.json>
```

退出码（**四类，别只看 0/1**）：

| 码 | 含义 | 该怎么处理 |
|---|---|---|
| `0` | 无 error | 可放行 |
| `1` | 存在 error | **禁止放行**，先清 T1 |
| `2` | **没有任何可分析的章节**（目录空／全是序章／全部读不出） | 不是"通过"，是**没查成**——先看跳过清单 |
| `3` | 有文件被跳过，其余已分析 | 质检未覆盖全部，别当成全过了 |

> 此前脚本遇到 GB18030 稿会抛 `UnicodeDecodeError`，解释器同样返回 `1`，
> 与"有 error"撞码，调用方分不清。**崩溃必须能和内容 error 区分开**，故拆成上表。

脚本会打印「跳过清单」并区分**预期内**（序章／番外／前言／后记／楔子）与**非预期**；
有非预期跳过项时**不要**把结果当成"已通过"。

**同时输出**：环境段占比 / 动作密度 / 神态密度 三项正向指标（用于"描写太薄"的诊断，见 `style-rules.md`）。

### 实测基线（2026-10-17 第一卷 50 章）

| 指标 | 均值 | 说明 |
|---|---|---|
| T1 命中 | **0** | 最毒套话一处没有——纪律有效时的正常状态 |
| 神态/千字 | 3.6 | **短板**；对话章仅 0.4~0.7（见下） |
| 环境段% | 27.0 | 健康 |
| AI味/千字 | 0.8 | 轻 |

### 两条线要分清（★ 校准原则）

| 线 | 算法 | 用途 | 本项目的值 |
|---|---|---|---|
| **目标线** | 本项目基线 **× 1.25** | 写作时争取达到（**进步线**） | 神态 **4.5**/千字（= 3.6 × 1.25）；对话章 ≥3.0；环境 ≥22%；AI味 ≤1.5 |
| **报警线** | **同类人类作品的上限 × 1.25** | 超了才报（**防误杀**） | ⚠️ **待补**——需人类样本，按 `好小说拆解库.md` 第五节「报警线校准表」填 |

> **为什么要分开**：文枢的"门槛校准原则"（人类上限 ×1.25）算的是**报警线**——防的是"人类作者也会这么写，你凭什么报警"。
> 而 4.5 是**目标线**——"比现在的自己好 25%"。两者性质不同，不能混用。
> **报警线如何补**：拿几段作者认可的同类作品（同平台网文）跑一遍本脚本，取该项密度的最大值 ×1.25。**样本槽位与校准表见 `好小说拆解库.md` 第四、五节**（该库同时是"通过项"的正面样本去处，只借结构不借文本）。

> **特别提醒**：对话/交底类章节如果神态密度 <1.0，对话会变成"念台词"——这类章全靠说话推进，神态是唯一的表情载体。

## 八、两条补充规则（去同质化）

> 以下两条此前只在"误杀防护 / T2 高频比喻"里隐含。**正式单列**，写时即守、复查时逐条过。
> 两条都属于"靠人/AI 判断"层（`analyze_arc.py` 与 `lint_prose.py` **不自动查**，只做辅助提示），不在 T1 硬禁之列。

### 规则 1 · 比喻必须长在故事自己的土壤

- **内容**：禁用与本书世界观 / 题材脱节的"通用套路比喻"——如都市文硬塞深海、宇宙、战阵意象；所有题材都来一句"像溺水的人抓住浮木""像风中残烛"。比喻的**本体应来自本书已建立的世界**（物件、场景、角色经验、设定名词）。
- **为什么**：套路比喻是 AI 与新手最容易复用的"安全牌"，读者一眼出戏，也最显同质化。
- **谁查**：**人工 / AI**（脚本可辅助——`lint_prose.py` 检"像 / 如 / 仿佛 + 高频泛化意象"，但"是否脱离本书土壤"必须人判）。与 T2「高频比喻」同源、但更强调"脱离世界观"这一判据。

### 规则 2 · 角色口吻遮名可辨

- **内容**：不靠"温和 / 冷酷 / 腹黑 / 毒舌"等**标签词**定义角色；让说话方式、用词、节奏、口头禅本身成为识别符——读者**遮住名字也能认出是谁在说话**。
- **为什么**：贴标签是"告诉"而非"呈现"，也是 AI 给人物注水的典型手法（与六门 C 心理直述同源）。
- **谁查**：**人工 / AI**（脚本难查，靠朗读 / 角色对照；落实见 `craft-toolkit.md` 上下文包协议里的"结构化细节表"——口头禅、用词习惯要写死，并行写作时尤其要显式给子代理）。
