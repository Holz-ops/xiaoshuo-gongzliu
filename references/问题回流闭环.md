# 问题回流闭环（人的反馈 → 规则 → skill 升级）

从 SKILL.md 本体搬出。核心一句话：**用户的每一条反馈都要变成规则**——出口有两条：进项目问题本，或进 skill 本身。

---

## 五步闭环

1. 口述问题 → 编号记入「待处理」（I-xx）
2. 给出判断 + 影响范围 + 2~3 档方案，等用户拍板
3. 改完移到「已修复」（F-xx），注明改了哪些文件
4. 提炼成规则 → 写进 `references/rules-from-mistakes.md`
5. **每轮结束产出《升级材料》** → 模板见 `assets/templates/升级材料模板.md`

---

## 升级材料（给下一次升级 skill 的原料）

**一轮**（一批章节 / 一次复查周期 / 一卷）走完之后必须出。**六路收集，不只靠"人出声"**：

| # | 来源 | 产出时机 | 里面有什么 |
|---|---|---|---|
| 1 | **人工改动 diff** | 作者改完 | 作者**具体动了哪些字**——最能反映其语感，AI 学不会的部分 |
| 2 | **五道门确认记录** | 每道门（①②③④ + ⑥ 出口） | 作者在哪一步退了、为什么退 |
| 3 | 脚本报告 | 每章／每批 | 哪些指标反复报警 → 规则没落到位 |
| 4 | **合卷分析** | 每批／卷末 | 趋势：人物缺席、节奏、重复模式 |
| 5 | 章纲偏差 | 章纲回填时 | 计划 vs 实际（方法层的信号） |
| 6 | AI 执行复盘 | 每轮 | 遇到的困难、发现的规律 |

**必填三栏**（缺一不可）：

| 栏 | 为什么 |
|---|---|
| **作者的意见（原话直录）** | **不转述**——原话才是判断"规则该定多严"的依据 |
| **提炼出的规则 + 归属** | 能数出来 → 脚本；要判断 → 提示词；是步骤 → 流程 |
| **待验证项** | 新规则未必对（如「他知道」被误列为必改），必须留验证口子 |

**产出位置**：`009 其他\问题本\升级材料-第N轮.md`（模板见 `assets/templates/升级材料模板.md`）

**与「自查报告」的区别**：自查报告给**作者**看（据此提意见）；升级材料给**下次升级**用（提炼规则）。
