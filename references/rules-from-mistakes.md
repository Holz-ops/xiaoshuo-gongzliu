# 踩坑 → 规则对照表

> **本文件仅适用单本长篇**：其中的具体案例（设定、数值、篇幅）为单书示例，
> 跨项目复用前须重写。项目 specific 的教训请写进该书自己的
> `009 其他\问题本\`，不要沉淀到这里。

来源：《我在星门修机甲》第一卷（36 章 / 7.8 万字）全程实录。每踩一次坑，就在这里加一条规则。

编号体系（沿用项目里的改进记录）：

| 前缀 | 含义 |
|---|---|
| I-xx | 待处理（已记录，未动手） |
| F-xx | 已修复 |
| T-xx | 结构待办（跨章节，非单章问题） |
| O-xx | 观察清单（风险，不一定要改） |

## 设定与一致性类

| 编号 | 踩到的坑 | 固化规则 |

| F-01 | 正文写「星历 47」，设定写「星历 267」，差 220 年 | **开写前先定唯一纪年并写进基准表**，正文任何年代数字先查表 |
| F-02 | 录音笔日期与抵达时间差七个月 | 涉及时间戳的地方，写在基准表的**时间轴**里，写章前先对轴 |

| F-04 | 人物编号与载具编号撞号 | 建**编号总表**，新增编号先查重 |
| F-08 | 站名前后不一致（第七 vs 第九） | 专名统一进基准表，一致性脚本扫描 |
| F-06 | 机体铭牌与女主机体同号 | 同名冲突**先考虑能否转化为剧情线索**（改成假编号，反成主线钩子） |
| F-07 | 女主前 16 章零出场 | 主要角色登场时间写进目录阶段，不许拖过卷的三分之一 |

## 流程与关卡类

| 编号 | 踩到的坑 | 固化规则 |
|---|---|---|
| G-01 | 一次把选题、梗概、目录、正文全写完让用户「一起看」 | **每步一停**：展示完整产出 + 自检打勾 + 三选项（通过/修改/重来）；未确认不动下一步 |
| G-02 | 凭记忆判断「走到哪一步了」，换会话就丢 | 用**进度卡**记录六步通过状态，新会话先读卡 |
| G-03 | 目录没确认就开始写正文，结构漂移后整批返工 | 目录通过前，正文一个字都不写 |
| G-04 | 章纲写得太虚（「他发现了一些线索」），正文卡住 | 章纲一句话必须含：核心事件 + 结果 + 留下的钩子 |
| G-05 | 复查只夸不查 | 复查必须拿问题本逐条打勾，输出硬伤/建议/通过三档 |
| G-06 | 让人先复查、机器人后查，人的时间耗在低级问题上 | **⑤→⑥ 自动衔接 + 复查三步走**：⑤ 写完不停顿自动进 ⑥，AI 自查 → AI 据报告改稿 → 才把「修改报告 + 改后文章」交人确认；意见编号入问题本。**门从 ⑤ 之后移到 ⑥ 出口**，人只做裁判不做搬运 |
| G-07 | 梗概凭空写，写完才发现基调不对 | 第 1 步先出**报告**（题材 + 基调 + 资料包），**梗概以报告为地基**；新书与续写两个入口共用同一份报告 |
| G-08 | 正文写完了，章纲还停在「计划」，后面的章节照过期地图接 | 每批正文写完必做**章纲回填**：按实际发生的事重写章纲，保留「计划 / 实际」两列并记偏差；偏差清单是复查的对照材料 |
| G-09 | 改稿**原地覆盖**，改前版本没留，事后想做"改前/改后"对照已不可能（真实踩过：第 17/18/23/27 章） | **改稿前先快照**：把这批要改的 md 复制到 `009 其他\版本\快照\<日期>-<批次>前\`，再动正文；改完在进度卡记一句快照路径。存放规范：`<日期>-<批次>前`，docx 快照存同一目录 |
| G-17 | 改稿时问题本在别的目录，来回跳很费事（用户："顺便把错题本也复制一个到文章里，这样好很多"） | 问题本留**两份**：**主本唯一**（`009 其他\问题本\`，长期台账）+ **工作副本**（`006 文章\错题本\`，改稿时就近看）。**主本一更新，副本就跟一遍；不一致时以主本为准** |
| G-16 | 把"待定"的稿子当成品放进「最终文章」（真实踩过：17~36 章还在改稿流程里，却被全部放进了最终文章） | **文章在哪一格＝走到哪一步**：扩写完→扩展文章；AI 查完**等人确定**→ai复查文章；人确定通过→人工复查文章；**真正定稿**→最终文章。**放最终文章前先问：人的那一关过了吗？** |
| G-15 | 校验词典把「合法简称」当「混用」→ 误报（真实踩过：司机口语「第七维修站」vs 正式全称「第七机甲维修站」） | 词典**只放真错写**，不放合法简称（口语简称、泛指都属正常）。判断标准：同一语境下不该同时出现两种写法的才列进来 |
| G-14 | 改完只在正文目录里生成，一堆文件混在一起，**人根本拿不到"这一批改了什么"** | 每批改完必出**批次成品包** `009 其他\批次成品\<日期>-<批次>（<章号>）\`：导读（含"要你回答的几个问题"）+ 本批改后成品 + 改动说明 + 自查报告。**这是给人读的唯一入口**，别让人去一堆文件里翻 |
| G-13 | 没写清"一本书一条流水线"，两本书的文件可能互相串（设定、章纲、进度卡混用） | **单书隔离**：一本书＝一条独立流水线（独立进度卡/章纲两条/三层检查/目录分层）；不许串、不许合、换书就新起一条；同一本的下卷用**回卷**不新起。起新书用 `scripts/init_book.py "书名" <父目录>`，目标非空则拒绝执行 |
| G-11 | 改稿时"问题出在哪"要靠通读全文去找，效率极低 | **三层分工**：① 文章层（写出来）② AI 检查层（查对不对：字数/一致性/穿帮）③ 人的层（查好不好，人提意见→AI 改→通过）。**问题先定位在哪一层，就回那一层找**（示意图 `流程图-三层分工.svg`） |
| G-12 | 章纲只有一条，写着写着偏了，接下来照哪条写说不清 | 章纲留**两条**：**先行章纲**（写前定、冻结、当对比基准）+ **总结章纲**（写完按实际总结、**后续以此为准**）；两条一比即偏差（示意图 `流程图-章纲两条.svg`） |
| G-10 | 生成新 docx 时用了**阿拉伯数字**命名（`第17章：上报.docx`），与项目既有的**中文数字**命名（`第十七章：上报.docx`）不同名 → 交付目录里出现"假重复"，还差点让人误判"旧版已被覆盖、原文已丢" | **交付命名必须与项目既有文件完全一致**：中文数字 + 全角冒号（`第{cn}章：{title}.docx`）。转换前先 `ls` 看一眼既有命名，再决定模板。（这个坑这次反而救了命——旧版没被覆盖才找得回来，但不能指望这种运气） |

## 工程与工具类

| 编号 | 踩到的坑 | 固化规则 |
|---|---|---|
| — | 初稿字数普遍比目标低 25~30% | 写完先跑 `count_chars.py`，别目测 |
| — | 编辑器 SDK 路径随版本变化导致转换失败 | 脚本里做**多路径探测** |
| — | 成对ASCII 标签（`<b>…</b>`）会被编辑器当 HTML 标签 → 转换前清洗。**注意：转换不会「静默产出空文档」，而是产出内容被改写的文档** | 转换前清洗代码围栏与成对 ASCII 标签；转换后**用文本长度比对 md 的净字数**（不看文件大小），并对超限项人工抽查 |
| — | 章号重排后旧 docx 残留，新旧混排 | **不删**：旧命名 docx 旧命名文件已**移入** `009 其他\版本\快照\<日期>-<批次>前\` 并在版本索引登记（**不是删除**） |
| — | 手抄字数表错位两行 | 章表字数一律由脚本生成，不手抄 |
| — | 上下文撑爆，靠记忆续写必丢设定 | 用**档案接管**：续写档案 + 上下文压缩包 + 改进记录 |
| **F-11** | **负面检测的正则凭直觉定，误报率极高**——同一轮连踩两次：「多顿号列举句」被误判为排比（每章误报 7~13 次）；「他知道／他明白」被列为"出现即改"，实测 50 章 9 处命中**全是正常写法**（"他知道等着是什么意思"） | **任何负面规则（禁用词、句式为、密度线）落地前，必须先在真实文本上跑一遍假阳性率**——命中处逐条人工过目，确认误报比例可接受才启用；否则降级为 warn 或收窄正则。**不许拿"直觉"当规则** |
| **F-12** | **批量重转覆盖了作者手改的文件**（第 1 章）——且常规恢复途径（编辑器临时副本、应用数据、系统还原点）全部无效 | 两条：① **覆盖前三重校验**——比目标文件修改时间 vs 上次生成时间／强制备份到 `版本\重转前备份-<时间戳>\`／时间戳异常**必须停下问**，不得继续；② **兜底恢复路径**——编辑器打开过的文档，其内容存于 `%TEMP%\workbuddy-editor-sdk-sandbox\tmp\doc\<服务号>\<会话ID>\data.tmp`，可按会话时间窗筛出并完整恢复（已实测成功救回 2,726 字） |

## 新增规则的位置

每完成一轮改稿，把新规则追加到对应分类下，格式为：

```
| 编号 | 踩到的坑 | 固化规则 |
```

不要修改历史条目——历史是证据，规则是结论，两者都要留。

## 工程与工具类（续：2026-10-17 第二批）

| 编号 | 踩到的坑 | 固化规则 |
|---|---|---|
| **F-13** | `analyze_arc.py` 用 `text.count(\\n——\\n)` 数字场景，**Windows 写的 CRLF md 永远数到 0 且不报错**（`paras` 那一路有 `l.strip()` 兜底所以照常，只有数字场景这一条静默失效）。实测：明明有 4/4/5 个场景分隔符，报告全是 0 | 读入后**先归一化行尾**再计数：`text.replace(\\r\\n,\\n\\).replace(\\r,\\n)`。凡是"按原始文本数字数"的指标，都要先问一句：换行符变了它还成立吗 |
| **F-14** | `analyze_arc.py` 的 `CHARACTER_LEVEL` 表**写死**了《我在星门修机甲》的角色（林北/老郑/艾米/沈默……）。换书后全部落空 → `casts` 为空 → 输出"无超过阈值的缺席"。**不是真没缺席，是根本没查**——同时破坏单书隔离（脚本里藏着别书的设定） | 跨项目复用的脚本**不得内置任何单书设定**。角色表/纪年/专名一律外置成按书读取的文件（如 `001 世界观\\人物表.txt`）；文件缺失时**明确报警**，不许静默输出空结果 |
| **F-15** | 人物出场靠**名字匹配**（`c in body`），而第三人称限定时主角通篇用"他"——第 2、3 章"周野"三字一次未现，但他是全程 POV。名字数不到他 ≠ 缺席 | 读出场矩阵必须补一条：**POV 主角永远在场**。名单匹配只能当线索，不能当结论 |
| — | 把合卷分析报告（带 `#` 标题的 md）和被分析的章节放进**同一个目录** → `check_consistency.py` 把它当成 markdown 残留，一次报 9 处 CONFLICT，全是我自己制造的 | 分析类产物与正文**分目录放**。脚本只扫一级 `*.md`，报告别和章节躺在一起 |
