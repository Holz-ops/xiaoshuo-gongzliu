# 六步主干详解（含两个入口与收尾）

结构：**两个入口（不算步、无门）→ 六步主干（①②③④ 各一道门；⑤ 与 ⑥ 自动衔接成「写查改闭环」，门在 ⑥ 出口）→ 收尾（不算步，前置：⑥ 的门已通过且不可从档案继承）→ 下一卷回到第 3 步**。

每步给出：目标 / 输入 / 动作 / 产出 / 完成标准 / 易错点 / 确认话术。

**贯穿全程的硬规则**：一步没确认，不许动下一步（**唯一例外：⑤ 生成正文完成后不停顿、自动衔接进入 ⑥**）。原稿只读。改稿前先确认范围与力度。**改稿前先快照。**

> **文章归位规则（没过人的关，绝不放最终文章）**：
> 刚扩写完 → `006 文章\扩展文章\`；AI 查完**等人确定** → `006 文章\ai复查文章\`；人确定通过 → `006 文章\人工复查文章\`；**真正定稿** → `007 最终文章\`。
> 把"待定"的稿子放进最终文章，等于把没验收的东西当成品交付。

> **快照规则**：动正文之前，先把这批要改的 md 复制到 `009 其他\版本\快照\<日期>-<批次>前\`，再开改；改完在进度卡上记一句快照路径。
> 理由：正文是**原地覆盖**的，不留快照就永远拿不回"改前版本"，事后再想做改前改后对照已经不可能。
>
> **同一条规则也管"清洗"**：清盗版水印、统一编码、去重复段这类操作**同样是原地覆盖、同样不可逆**，
> 动之前也要先快照，且**产物另存一份，不要在源目录上就地改**（源目录只读）。
> 实测教训：一段正则清完水印，如果同时吃掉了正文（水印块的正则常带 `[^\n]{0,90}`，
> 会把紧跟其后的句子一起卷走），没有快照就再也分不清"原文本该是什么"。

## 入口 A：头脑风暴（选题发散）· 新书入口，不算步、无门

**目标**：在**既定方向下，把「可以写什么」铺开，不做判断。**

**输入：用户给的大方向（如「机甲维修」「年代文」「重**生复仇」），可能还有平台偏好与忌讳。

**动作**

1. 先复述方向，确认理解无误（这一步不产出，只是对齐）
2. 发散出 **≥5 个备选方向**，每个写五件事：题材子类型、主角身份、核心冲突、卖点、风险
3. 对每个方向给一句「为什么值得写 / 为什么不选」
4. 标出 2~3 个推荐项，说明推荐理由

**产出**：选题备选池（表格）

**完成标准**：≥5 个备选；每项五要素齐全；有明确推荐与理由

**易错点**

- 只给 1~2 个选项 → 等于替用户做了决定，后面返工率极高
- 只写卖点不写风险 → 用户无法判断
- 发散时就开始写正文片段 → 越界

**确认话术**：

> 以上是 5 个备选方向，推荐第 2、3 个，理由是……请确认：**1 通过，进入报告（第 1 步）/ 2 调整某几个 / 3 换个方向重新发散**

## 入口 D：样本拆解（可选支线，不算步）

**什么时候用**：① 开书前想找"好在哪里"的参照；② ⑥ 复查发现"某类场面总写不好"；③ 要补 `references/好小说拆解库.md` 的空槽位或校准报警线。

**输入**：作者提供的好文本（网文开篇 3 章 / 对话段 / 爽点段 / 喘息段 / 公版白描段），**每份附一句「我要它的哪一点」**。

**动作（四步一循环）**

1. **选样定焦**：确认"要它的哪一点"（信息释放速度？动作落点？爽点节奏？）——**没这句话不拆**，否则拆出来是读后感。
2. **跑客观指标**：`python scripts/lint_prose.py <样本目录> --json 样本.json`；若这批兼作校准样本，再跑 `python scripts/calibrate.py <样本目录> --out 报警线.md`。
3. **按拆解卡逐位拆**：7 个观察位逐个填（这一句在干什么 / 信息怎么给 / 情绪落在哪 / 节奏 / 视角与距离 / 钩子或回响 / 可迁移的做法）。
4. **提炼成打法并编号**：写成 `P-xx` 一行（打法 / 一句操作 / 适用场景 / 来源），追加到库的「打法清单」；拆解卡存进库第三节。

**产出**：`拆解卡-<样本名>.md`（或库内一节）+ 新打法 `P-xx` +（校准样本时）`报警线.md`

**完成标准**：每个样本都有"可迁移的做法"**且已编号**；报警线表由脚本产出并回填 `anti-ai-rules.md`；单条引用 ≤3 句且标出处

**易错点**

- 只写"写得好 / 很真实" → 不是拆解，是读后感
- 拆完不给编号 → ④ 章纲引用不了，等于白拆
- 大段复制原文入库 → 版权与"借结构不借文本"双违规
- 拿 AI 生成的段落当"人类样本"校准 → 报警线被 AI 拉低，越校越像 AI

**确认话术（本支线唯一一道门）**：

> 拆解完成：样本 N 篇 → 新打法 P-xx…；报警线已更新（神态 X / 环境 Y / AI味 Z）。请确认：**1 入库 / 2 某条拆得不对 / 3 换个角度重拆**

## 第 1 步：报告（定题材 · 定基调 · 备资料）

**目标**：从发散收敛到一个明确结论——**到底写什么**。

**输入**：入口 A（头脑风暴）确认的方向 / 入口 B（素材体检 + 定基准）的结果。

**两个入口共用同一份报告，填法不同**：

| 入口        | 这份报告要回答                        |
| --------- | ------------------------------ |
| 新书（从零）    | 写什么 + 基调是什么（风格、情绪、节奏、读者预期）     |
| 续写（洗稿/续写） | 现在是什么 + 基调往哪调（现状、已有基调、要延续还是纠偏） |

**这份报告是梗概的地基**：梗概不凭空写，照报告里定下的题材、基调与资料去写。

**动作**

1. 填选题报告：题材、平台、目标读者、字数与卷数规划、核心卖点一句话
2. 与同类作品的差异点（凭什么有人看）
3. 风险与规避（这个题材容易踩什么坑）
4. 开头三章的方向（不是正文，是方向）

**产出**：`报告.md`（新书：选题与基调；续写：现状与基调）

**完成标准**：能一句话说清「写给谁看的什么故事」；**基调写死**（风格 / 情绪 / 节奏 / 读者预期）；字数与卷数可计算；梗概要用的资料齐备（人物方向、场景方向、冲突方向、开篇方向）

**易错点**

- 卖点写成「文笔好、剧情精彩」→ 无效，必须是可感知的具体差异
- 不规划字数 → 后面目录阶段必然章数失控（真实踩过：按旧节奏定 24 章，改规格后实际需要 70 章）

**确认话术**：

> 报告已出：题材是「……」，基调定在「……」（风格 + 情绪 + 节奏），梗概所需资料已备齐。请确认：**1 通过，进入梗概 / 2 修改某几项 / 3 重做**

## 第 2 步：梗概

**目标**：把选题变成可执行的故事骨架。

**输入**：确认过的选题报告。

**动作**

1. 主角：身份、处境、欲望、弱点、金手指、性格信条
2. 主线：三幕或四幕结构，每幕一句话
3. 核心谜题 / 核心冲突：一句话说清
4. 势力与人物表：谁、要什么、与主角的关系
5. 卷结构：每卷一句话 + 字数
6. 结局方向（不写细节，写方向）
7. 卖点落点：爽点/悬念/情感分别在第几卷兑现

**结构补强（可选，作为上面七要素的深化——不替代、不动现有门）**

> 七要素已经能跑，但容易停在"清单式"。想让骨架更结实，可补三样；填法模板见 `craft-toolkit.md` 人物档案卡。

- **驱动力三角（每个主要角色一张）**：写清角色表面**想要**什么（want）、深层**需要**什么（need，往往自己不知道）、**恐惧**什么（fear，决定压力下的选择）。三者张力越大，角色越立得住；缺了恐惧，角色在压力下没有"两难"。
- **角色弧线（主角必写，配角选写）**：起点信念 → 经历什么关键事件 → 终点信念是否转变。弧线不必都"变好"，但必须有**位移**，否则人物一条直线、后期失真（正是 `craft-toolkit.md` 逐章情绪弧线要防的）。
- **三幕节点清单（主线对照）**：按总章数 × 比例锁定关键节点，避免中段塌方：

  | 节点 | 位置（占总章数） | 这一节点要发生 |
  |---|---|---|
  | 打破平衡 | ~12–15% | 主角被推离日常，主线正式启动 |
  | 第一幕落点 | 25% | 进入新世界/新规则，不可逆 |
  | 中点（反转） | 50% | 表面胜利或惨败，局势翻转，目标升级 |
  | 一无所有 | ~75% | 主角失去最多，跌到谷底 |
  | 高潮 | ~90% | 与核心冲突正面决战 |
  | 结局 | 100% | 收束（方向，不写细节） |

  > 比例按"章数×百分比"换算成具体章号填。卷结构（上面的第 5 点）与这张节点表应互相印证——卷末正好落在某个节点上。
  > 也可对照 `references/三幕十五节拍表.md` 的 15 节点 / 10 原型做节拍对齐（尤其商业类型文的「承诺兑现期」该兑什么）。

**产出**：`梗概.md` + `设定基准表`（纪年、时间轴、专名、编号总表）

**完成标准**：每个要素都能回答「凭什么」；设定基准表可作为后续校验词典

**易错点**

- 梗概写成流水账（他先去 A 再去 B）→ 没有因果，正文会散
- 不建设定基准表 → 后面必然出现纪年/日期/编号冲突（真实踩过：星历 47 vs 267；录音笔日期差七个月；编号撞号）
- 人物表不写「要什么」→ 配角会沦为递消息的工具人

**确认话术**：

> 梗概已出，主线是「……」。请确认：**1 通过，进入目录 / 2 修改某部分 / 3 重做**

## 第 3 步：目录（把结果定下来）

**目标**：把梗概拆成章，把结构锁死。

**输入**：确认过的梗概。

**动作**

1. 算章数：**目标字数 ÷ 每章字数(2000~3000)**，不要沿用旧节奏
2. 分卷排章，每章一个标题
3. 每章配一句话（这一章做什么）
4. 标注结构分段（开场 / 中段 / 收束）与卷末收束方式
5. 标出可加密的位置（之后要加章插在哪）
6. （可选）每章标一句**悬念类型 / 伏笔操作**（埋设 / 回收 / 提一句），对接 `craft-toolkit.md` 的章末钩子五型与伏笔登记表——也让 `scripts/analyze_arc.py` 的节奏 / 伏笔闭环检测能读到标记。

**产出**：`目录与章纲.md`

**完成标准**：章数与字数目标吻合；每章有标题与一句话；卷末收得住；分段标注清楚

**易错点**

- 边写正文边定目录 → 结构漂移，卷末收不住
- 章数沿用旧稿 → 严重不足或严重超出
- 一句话写成「主角继续调查」→ 等于没写，必须是有动作有结果的句子

**确认话术**：

> 目录共 X 章，分三段：1~N 开场 / … 。请确认：**1 通过，进入章纲 / 2 调整某几章 / 3 重排结构**

---

## 第 4 步：章纲一句话（要发生的事情）

**目标**：每章写清楚「这一章要发生什么」，为正文提供唯一依据。

**输入**：确认过的目录。

**动作**

每章写 30~80 字，包含三件事 + 一个必填字段：

1. 这一章发生的核心事件
2. 这一章的结果（人物或局势发生了什么变化）
3. 这一章留下的钩子（下一章靠什么接住）
4. **本章打法 `P-xx`（必填）**：从 `references/好小说拆解库.md` 第六节「打法清单」选一个写在行末；纯过渡章写 `P-00` 并注明「仅推进 / 喘息」。

> **为什么必填**：没有编号，"参考好样本"就是一句空话；有了编号，⑥ 复查才能反查"你标了 P-03，正文里到底用了没有"。**标了没用 = 承诺未兑现，进硬伤。**
>（可选）在钩子后补一句「悬念类型 / 伏笔操作」，并加节奏标记 `[爆]/[紧]/[缓]/[静]`（高强度 / 缓冲），对接 `craft-toolkit.md` 的钩子五型与伏笔登记表。`analyze_arc.py` 的「认知过山车」检测会读这些标记；不标该检测跳过。

**产出**：章纲表（可并入目录文件）

**完成标准**：每章 30~80 字；三要素齐全；**每章标 ≥1 个打法编号（P-xx，纯过渡写 P-00）**；不写细节、不写对话、不写心理描写

**易错点**

- 写成「他发现了一些线索」→ 不可执行，正文会卡住
- 连续几章的钩子同质（都是「有人来过」）→ 后面章末必然重复
- 章纲里已经写了对白 → 把创作提前消耗了，正文会变成扩写填充

**确认话术**：

> 章纲已写完 X 章，每章一句话。请确认：**1 通过，开始写正文 / 2 修改某几章的章纲 / 3 重写**

## 第 5 步：生成正文

**目标**：按章纲那一段话，扩展成 2000~3000 字的成稿。**本步不设门**——达标即不停顿、自动进入 ⑥（写查改闭环，见第 ⑥ 步）。

**输入**：确认过的章纲。

**动作**

1. **按批推进，每批约 10 章**，不要一次写 20 章以上
2. 每章结构：环境锚点 → 推进一条线 → 章末钩子
3. 写完立刻跑脚本：字数轨 + 一致性轨
4. 字数不足用「回填清单」补，禁止删环境描写凑字数
5. 转 docx，命名「第N章：标题」（全角冒号）。**不删任何文件** —— 若存在旧命名的 docx，先用规范名写入新文件，再把旧名文件旧命名文件已**移入** `009 其他\版本\快照\<日期>-<批次>前\` 并在版本索引登记（**不是删除**）

**产出**：章节 md + docx

**完成标准**：字数全在区间；一致性无硬伤；章末有钩子；文风与样章一致

**易错点**

- 初稿普遍比目标低 25~30% → 写完先跑脚本，不要目测
- 为压字数砍环境与动作 → 信息都在、画面没有（用户已提过 I-01）
- 章号重排后旧 docx 残留 → 交付目录新旧混排
- 成对 ASCII 标签会被当 HTML 标签 → 转换前清洗（**不会产出空文档，但正文里的不等式 `HP<100` 不受影响**）

**确认话术**：

**本步不设门**：达标即**自动进入 ⑥**，不停顿、不等确认。交接时说明本批结果，随即连做 ⑥ 的分析与改稿，只在 ⑥ 出口一次性交付「修改报告 + 改后文章」并等待确认。

**衔接话术**（不是确认请求，是告知后继续）：

> 本批 10 章已完成，字数 2000~3000 全部达标，一致性扫描 X 处待核对；章纲已按实际内容回填，偏差 X 处（新增/删除/挪位）。**以下不停顿，直接进入 ⑥ 复查：AI 分析 → 出分析报告 → 据报告改稿 → 同时输出修改报告与改后文章，届时请你确认。**

## 第 5B 步：章纲总结（先行 / 总结两条，不单独设门）

**先把章纲分成两条**：

| 条 | 名 | 定于 | 能否改 | 用途 |
|---|---|---|---|---|
| 第一 | **先行章纲** | 第 ④ 步（写作前） | **冻结** | 写正文的依据 + 将来对比的基准 |
| 第二 | **总结章纲** | 本步（写完后） | 可更新 | **后续一律以它为准** |

**目标**：正文是按先行章纲写的，但写的过程一定会偏——加了个角色、改了个结果、换了个钩子。不总结，先行章纲就是一张**过期地图**，后面的章节与第二卷会照着错的信息接。**接下去写只能照实际的来**，所以总结条是活的，先行条冻结不动（一改就没法对比）。

**输入**：本批正文 + 原来的章纲。

**动作**

1. 逐章对照：章纲里写的「要发生的事」，正文里实际发生了没有？发生得一样吗？
2. 把章纲重写为**实际发生的事**：核心事件 + 实际结果 + 实际留下的钩子
3. 记下偏差：新增了什么、删了什么、挪到了哪一章
4. 检查**接口**：本批最后一章留的钩子，下一批第一章的章纲接得住吗
5. 标注**未兑现的计划**：章纲里计划了但正文没写的，要么补进后续章纲，要么正式删掉并说明

**产出**：更新后的章纲表（**计划 / 实际两列**）+ 偏差清单

**完成标准**：每章章纲 = 正文实际内容；偏差有记录；下一批的接口明确

**易错点**

- 不回填就写下一批 → 前后接不上
- 回填时把「计划」那列也改掉 → 偏差就看不出来了，**两列都要留**
- 只回填不检查接口 → 钩子悬空，读者觉得断层
- 这是「总结重写」，不是「正文改写」——正文毛病留给复查

**确认话术**：**本步不单独设门**——⑤ 本身也不设门，回填结果并入 **⑥ 出口的输出包**（修改报告 + 改后文章）一起确认，话术见第 ⑥ 步。

---

## 第 6 步：复查（三步走：AI 自查 → AI 改稿 → 人确认）

> **本步由 ⑤ 自动衔接进入**：⑤ 生成正文一完成，**不停顿、不等确认**，直接进本步。本步内部 AI 连做「分析 → 出分析报告 → 据报告改稿」，**只在全部改完之后设一道门**。

**目标**：机器人先按问题本分析一遍，再把低级问题**自己改掉**；人只看「改得对不对」。不是「再读一遍」，是**拿问题本逐项打勾并逐条落地**。

**输入**：本批正文 + 反馈表（规则库 + 项目改进记录）。

**动作**

**第 1 轮：AI 自查（依据问题本）**

问题本两本：**项目问题本**（项目的 `改进记录`，I/F/T/O 编号表）+ **通用问题本**（`references/rules-from-mistakes.md`）。

1. 跑脚本：字数轨 + 一致性轨 + **文本轨**（`lint_prose.py`）
2. 对照两本问题本**逐条打勾**，标复发 / 未复发 / 不适用
3. 对照「前 10 章检查清单」检查开局（若本批含前 10 章）
4. 输出 `自查报告.md`（＝ 分析报告），分三档：硬伤 / 建议 / 通过

**第 2 轮：AI 依据报告改稿（自动，不停顿）**

自查完**不交给人类先改**——AI 自己按报告逐条落地：

1. 字数不足 → 用回填清单补描写（**禁删环境凑字数**）
2. T1 命中 → **清零**（error 级非零不放行）
3. 硬伤（设定冲突 / 时间线错乱 / 字数越界 / markdown 残留）→ 逐条修
4. 对话章神态偏薄 → 补神态（对话章目标 ≥3.0/千字）
5. **改稿前打快照**；改后稿落 `006 文章\ai复查文章\`，改前版本留 `006 文章\扩展文章\`（可对照、可回滚）
6. 输出 `修改报告.md`：改动清单（章号 / 问题 / 改法 / 前后对照）

**第 3 轮：人工确认（★ 门在这里）**

1. **同时输出「修改报告 + 修改后的文章」**，然后停下等确认
2. 人提的新意见 → 编号进项目问题本（I-xx）（人说「这条不算问题」也照记）
3. 按意见再改一轮 → 再提交确认（**不进入下一步**）；通过后交付，问题本 I-xx 移到 F-xx

**产出**：`自查报告.md`（第 1 轮）+ `修改报告.md`（第 2 轮）+ **修改后的文章**（第 2 轮）+ 问题本更新（第 3 轮）

**完成标准**：问题本每条都有结论（复发 / 未复发 / 不适用）；硬伤已按报告改掉；**「修改报告 + 改后文章」已同时输出并经人确认**；人提的新意见已编号

**易错点**

- ⑤ 写完停下来等人点头 → 破环设计，人的时间又浪费在机器本该抓的低级问题上
- 自查只夸不查、或查完不改 → 等于没做
- 把「初稿 + 待办清单」丢给人让人自己改 → **违背本步设计**，必须是改完的稿子上门
- 只查字数不查一致性 → 硬伤留到读者眼里
- 改稿前不打快照 → 改坏了永远拿不回原版本
- 人提的意见不编号 → 下次照犯

**确认话术**：

> 本批已完成「AI 分析 → 据报告改稿」，现将**修改报告**（硬伤 X 处已改、建议 Y 条已落地、逐条改动前后对照见报告）与**修改后的文章**（共 N 章，已落 `ai复查文章`）一并附上。请确认：**1 通过，进入交付 / 2 按修改报告再调整某几处 / 3 有新的意见要加**。
> **⑥ 复查通过后，我会落盘交付并更新问题本。**（请确认第 ⑥ 步已通过——我不会从档案文件推断这一点。）

## 收尾：交付与交接（不算步；前置：⑥ 的门已通过，不可从档案继承）

第 ⑥ 步的门通过后执行（该事实**必须当场向用户确认**，不得从进度卡/压缩包/续写档案继承）：

1. md → docx（命名「第N章：标题」，全角冒号）。**不删任何文件** —— 旧命名 docx 旧命名文件已**移入** `009 其他\版本\快照\<日期>-<批次>前\` 并在版本索引登记（**不是删除**）
2. 转换后校验文本长度（`md2docx.py` 内置，比对 md 净字数与 docx 实测字数）
3. 问题本同步：I-xx 移到 F-xx，注明改了哪些文件
4. 更新进度卡与续写档案；上下文超 60% 时产出上下文压缩包

### 交付后的验收清单（三项全对才算交付完成）

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | **章纲一句话已变成「实际版」** | 每章的「实际发生」列已填、「偏差」已记；**「计划」列保持原样未改**——改了就看不出偏在哪 |
| 2 | **目录与文章对上了** | 目录里 N 章 → 交付目录里 N 个 docx，章号与标题一一对应，无缺章、无多余；若交付目录有旧命名文件，已旧命名文件已**移入** `009 其他\版本\快照\<日期>-<批次>前\` 并在版本索引登记（**不是删除**） |
| 3 | 问题本与档案已同步 | 本轮 I-xx 已移到 F-xx（注明改了哪些文件）；进度卡、续写档案、章表字数已更新 |

> 对账用脚本，不要目测：`python scripts/count_chars.py <md目录>` 会列出全部章号与字数，缺章会直接从列表里看出来。

## 关于「破门」

如果用户明确说「不用确认了，直接往下写」，视为**一次性放行**，仍要在状态卡上记为「跳门（用户授权）」，并在下一步产出时把前一步的结果一并展示，方便补确认。

> **⑤ → ⑥ 不算破门**：这是**设计内的自动衔接**（见第 ⑤、⑥ 步），不需要用户授权、也不必记为「跳门」。自动衔接在 ⑥ 出口照常设门。
> 除 ⑤→⑥ 这一处设计内衔接、以及用户明确授权外，任何形式的跨步都是错误。
