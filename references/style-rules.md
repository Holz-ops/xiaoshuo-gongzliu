# 文风规范

## 基调

- **短句白描 + 嘴碎内心戏**。吐槽可以，抒情不行。
- 一句一个信息，少用从句。
- 段落短：对话段落通常 1~3 句。

---

## 全局排版规范（★ 一次写死，全卷不得分叉）

> **为什么单列一节**：曾经吃过亏——规范里没写的东西，各个写手必然各写各的。
> 实测出现过 **ASCII 引号 / 直角引号 `「」` / 中文弯引号 `“ ”` 三套并存**（全卷 2400+ 处不一致）。
> **凡是要全卷统一的，第一天就写死；不要指望事后扫。**

| 项 | 规定 | 禁止 |
|---|---|---|
| **引号** | `“ ”`（中文弯引号） | ❌ `「」`（日式／港台写法）、❌ ASCII `"` |
| **省略号** | `……`（六点） | ❌ `...`、❌ `。。` |
| **破折号** | `——`（两个全角破折号）；**正文中每章 ≤3 处** | ❌ `--`、❌ 单个 `—` |
| **场景分隔** | `——` **独立成行** | ❌ `---`（md 会解析成水平线，转 docx 时**整行丢失**） |
| **顿号／逗号** | 全角 `、` `，` | ❌ 半角 `,` `.` |
| **书名号** | `《》` | ❌ `<>`、❌ 引号代书名号 |
| **数字** | 中文语境用汉字（八百一十七块）；编号与型号用阿拉伯（WX-3806、天柱-Ⅳ·07） | ❌ 混用 |

**场景分隔符的实测结论**（不要"修"它）：`——` 独立一行，**转 docx 时会被渲染成横线（段落边框）**——
这是**有效效果**（比一串破折号字符规整得多），已由作者确认采用。
**md 里的 `——` 不能删**——它是横线的来源。

**章内不使用小标题**：全卷统一用场景分隔符切场景，**不用「一、二、三」**（曾出现全卷唯一特例，被作者要求删除）。

---

## 分段偏好

- **同一动作 / 同一句话的临时停顿，不独立成段**（作者实测偏好，从改动 diff 中提炼）
  - 反例：「他攒下的——」／「差八百。」分两段
  - 正例：「他攒下的——差八百。」并作一段
- 段落短：对话段落 1~3 句
- 场景转换、时间跳跃 → 用 `——` 分隔，**不用空行堆叠**

## 禁用清单

| 禁用 | 原因 | 替代 |
|---|---|---|
| 四字格堆砌（「瞳孔骤然收缩」「浑身血液几乎凝固」） | 网文里读着像 AI 模板 | 写具体动作与可感细节 |
| 三个以上连用形容词 | 空 | 留一个，换成名词或动作 |
| 抒情句（「仿佛在诉说着什么」） | 打断节奏 | 删 |
| 「他心里很复杂」式内心直述 | 不可见 | 写眼神、停顿、手上的动作 |
| 「他说 / 她看了他一眼」连着用 | 没有画面 | 插入动作节拍 |

## 环境：用可感细节，不用形容词

每场戏开头 2~3 句锚点，从下面**四选二**：

- 温度差（进门打了个激灵 / 铁皮被晒得烫手）
- 光线来源（一半坏掉的荧光灯 / 手电扫过的范围）
- 声音（永远在响的工地声 / 风穿过铁皮缝）
- 气味与质地（机油味 / 落在嘴里发涩的灰 / 脚下打滑的油渍）

规则：

- 每处不超过 3 句
- 给每个主要场景建**母题库**（如：城市=灰/铁皮棚/暗红的天；维修站=坏灯/油渍/旧件袋；办公楼=冷气/能照见人影的地砖），反复调用，形成辨识度
- **环境不是可压缩项**。为压字数砍环境，是得不偿失（用户反馈 I-01 的病根）

## 动作与表情：落到手上

- 主角的手永远在干活：拧、擦、摸、量
- 紧张不写「很紧张」，写「指节发白」「手心出汗沾在螺栓上」
- 给每个常驻角色配 1~2 个**习惯动作**（磕烟灰、端那杯凉茶、合记录夹、挽袖口），反复出现即为人物标识
- 表情只写看得见的部分：眼神、嘴角、停顿的时长

**样例对照**

改前：
> 他把那张纸折好，揣进外套内袋，坐班车去了联合指挥部。接待他的是个三十多岁的干事，姓蔡，戴眼镜，说话很快。"什么事？"

改后：
> 他把那张纸折成四折，揣进外套内袋，出门拦了一辆去城东的班车。班车是铁皮敞篷的，一路都在抖，风里裹着工地的灰，落在嘴里发涩。到站时他拍了拍肩，肩上落了一层白粉。
> 联指的楼是三层灰楼，台阶被踩得发亮。大厅里冷气开到十几度，他一进门打了个激灵，低头看了一眼自己那双沾了机油的靴子，往里收了半步。
> 接待他的是个三十多岁的干事，姓蔡，戴眼镜，说话很快。他抬头看了林北一眼，视线在他袖口的油污上停了一下。"什么事？"

## 章末钩子

每章必须收在钩子上。类型交替使用，避免同质化：

| 类型 | 做法 |
|---|---|
| 信息钩 | 抛出一个改变判断的新信息 |
| 抉择钩 | 主角必须二选一，本章不答 |
| 代价钩 | 得到某物但付出代价 |
| 悬念钩 | 有人来过 / 有人跟着（**最多连续用一次**） |

## 字数不足时的回填清单（按顺序补，不要删环境）

1. 环境锚点是否齐全（开头 + 场景转换处）
2. 对白前后的动作节拍
3. 技术/流程细节（维修步骤、检测曲线、账目数字）
4. 增加一个对话回合（反驳或追问）
5. 主角的内心吐槽（推进判断，不抒情）
6. 一个配角的反应镜头

## 技术流爽点

爽点 = **技术碾压打脸**，不是吵架赢。

结构：外行/权威下结论 → 主角指出真正的病根（给出可验证的细节）→ 对方不信 → 实测打脸 → 主角给出别人给不了的方案。

技术细节要真实可感：零件名、工具、读数、公差、流程顺序。宁可少写，不要写错。
