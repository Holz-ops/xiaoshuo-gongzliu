# 逐章「为什么」分析工作流（整本小说拆解 SOP）

> **用途**：拿到一本电子书，回答"它为什么好看/为什么有人追"，并把结论变成**可迁移的打法**。
> **不是读后感**：每一栏都要落到机制，且每条结论都要能回答"改成另一种写法会怎样"。
> **实测规模**：《红楼梦》120 回 → 12 批 × 10 回 → 120 张卡片 → 12.7 万字，5 个分析员并行约 6 分钟/人。

---

## 一、六步总览

```
① 取文 → ② 切章 → ③ 体检 → ④ 逐回卡片（10 回/批）→ ⑤ 批次机制 → ⑥ 卷级汇总
```

| 步 | 产物 | 脚本/模板 |
|---|---|---|
| ① 取文 | `.txt` / `.epub` | — |
| ② 切章 | `chapters/第NNN回：标题.md` + `_目录.md` | `txt_split.py` / `epub_extract.py` |
| ③ 体检 | 缺陷清单 | `chapter_health.py` + `_源文件缺陷.md` |
| ④ 逐回卡片 | `reports/第NN批（第A-B回）.md` | `assets/templates/逐章为什么分析模板.md` |
| ⑤ 批次机制 | 同上（报告后半） | 本文件 §四 |
| ⑥ 卷级汇总 | `reports/卷级汇总.md` | 本文件 §五 |

---

## 二、① 取文与 ② 切章

**格式优先级**：`.txt`（最稳）> `.epub` > `.docx` > 文本型 `.pdf`；`mobi/azw3` 先转 epub；扫描版 PDF 无 OCR 不可用。

```bash
# txt（自动识别 utf-8 / gb18030）
python scripts/txt_split.py <book.txt> <chapters目录> --dry-run   # 先看能切几章
python scripts/txt_split.py <book.txt> <chapters目录>

# epub（无 DRM）
python scripts/epub_extract.py <book.epub> <chapters目录> --dry-run
python scripts/epub_extract.py <book.epub> <chapters目录>
```

**切章三条硬规则**：

1. **章号按出现顺序编号，不解析中文数字**——「一一九 / 一二零 / 十一」混写，解析必错。
2. **回目后必须跟分隔符**（空白或标点），否则正文「第四回中既将…」会被当成回目（实测切出 121 章）。
3. **简写回目需剥前缀**——源文件「十三　回秦可卿…」多排一个「回」，属于章号标记而非标题。

## 三、③ 切章后体检（★ 分析前必做）

```bash
python scripts/chapter_health.py <chapters目录> --min-chars 4000
```

查四件事：**重复段**（>40 字段落出现 ≥2 次）、**截断嫌疑**（末行非收束标点且非章回体套语）、**过短章**、**空章**。

**脚本抓不到、必须人看的**：语义错接。实测《红楼梦》第 55 回在「我有一件大事」处截断，后接续书末回——字数正常、标点正常，只有读到一半才发现。做法：

- 每批分析前**抽读第 1 回与最后 1 回的末三段**；
- 发现异常立刻登记 `chapters/_源文件缺陷.md`（回号/位置/影响/是否可恢复）；
- **缺陷回的报告顶部必须加警示**，该回只按可用部分分析。

**已知噪声处理**：OCR 错字与符号污染（`撰此>一书`、`锦衣纨э`）→ 只摘无噪声短句，不据噪声判断文笔。

## 三B、③B 引文回源（**卡片写完、交批之前跑**；凡引用原文必过）

放在这里是因为它只依赖切章结果；实际执行时点在 ④ 每批卡片产出之后、装进批次成品之前。

分析稿里每一条"原文引用"都要能被带回源文件找到。**这是机器能判的事，不必靠自觉**：

```bash
python scripts/check_quotes.py <分析稿.md> --src <源文件目录> [--map 篇名映射.json]
```

- **判定**：引文须逐字存在于源文件；用 `……` 省略时，省略号两侧各自须是连续片段；比对时两侧都去空白，源侧另去盗版水印块。
- **动作**：核对不上 → 先换成原文里的真实片段；换不到 → **去掉引号**，宁可不引，不可编造。
- **退出码**：0 全部通过 / 1 有 FAIL（不放行）/ 2 没抽到引文（不是通过，是没查成）/ 3 部分篇目未匹配到源文件（用 `--map` 补）。
- **多候选**：分卷拆包（`(1)(2)(3)`）或跨目录重复收录时，脚本按「任一命中」核验，不会挑错分片。

**量级参考**（会过期，只看量级）：某次 48 篇实测，首轮引文回源命中率仅 **33.7%** —— 三分之二的"原文引用"在源文件里不存在。写成"请注意核对"是拦不住的，必须当卡点跑。

> 拿不到源文件时（只有分析稿、没有原文），这一关**过不了就等于没过**，不能默认通过。

## 四、④ 逐回卡片 + ⑤ 批次机制

### 4.1 每回一张 7 栏表（缺一不可）

| 栏 | 要求 | 反例 |
|---|---|---|
| **章主题** | 这一回在全书里的**功能**（推进/揭示/转折/喘息） | "本章讲了宝玉去见黛玉" |
| **核心观点** | 这一回要让人相信什么判断 | "描写了贾府的繁华" |
| **关键论证** | 支撑该判断的**情节链**，具体到事件 | "推进了剧情" |
| **结论** | 回末局势/人物发生的**不可逆变化** | "本章结束" |
| **为什么翻下一回** | 具体钩子机制（未解/威胁/新信息/情绪缺口） | "留下悬念" |
| **可迁移打法** | `P-xx` + 一句操作 | "写得很精彩" |
| **反事实** | 删掉/换写法，读者会缺什么 | （空着） |

### 4.2 批次机制（每 10 回一份）

1. **承诺—兑现曲线**：每回打 1~5 分，看三个信号——承诺高兑现低＝画大饼；连续高兑现＝爽点通胀；连续低＝流失区。
2. **情绪引擎**：主引擎（打脸/升级/解谜/情感补偿/恐惧/喜剧/代入）、换档点、呼吸章。
3. **章间逻辑五型**：因果 / 递进 / 对照 / 伏笔 / 平行；每型写清"哪几回之间"。
4. **本批新打法**：每条给 ID、一句操作、适用场景；**编号区间由分派方预设**，防止并行冲突。

### 4.3 并行分派（10 批以上时）

- 每个分析员 **2 批（20 回）** 为宜；再多会失真。
- prompt 必须含：章节 glob 路径、必读的样板报告、7 栏结构、编号区间、质量红线、写完自检。
- **编号区间先分配**（如 A 用 P-48~P-73、B 用 P-74~P-99），否则必然撞号。

## 五、⑥ 卷级汇总（全书读完后写）

| 模块 | 内容 |
|---|---|
| **全书一句话** | 它凭什么让人读完、且愿意重读 |
| **盛衰/情绪曲线** | 分 5 段，标出"顶点"与"转折点"（注意：顶点常不在最后） |
| **承诺/判词兑现表** | 逐人逐条：承诺 → 兑现方式 → 兑现回 → 明/暗兑现；算兑现率 |
| **结构单元** | 每 10 回一个功能块，一句话说清功能 |
| **打法总表** | 把上百条 `P-xx` 归成 8~10 大类，每类给代表打法 |
| **可迁移结论** | 10 条以内，每条必须能落到操作 |
| **已知缺陷** | 源文件问题、分析未覆盖的部分 |

**卷级汇总的三种高价值发现**（《红楼梦》实测）：

1. **顶点位置**：第 18 回省亲是全书最高点，之后所有热闹都是"最后一次"的变奏。
2. **转折性质**：第 74 回抄检把矛盾从"人与人"改成"人与制度"，此后所有死亡都是内耗。
3. **兑现方式**：判词不是一次性剧透，是分期付款的账单——重读价值由此产生。

## 六、质量红线（五条，违反即返工）

1. **只借结构不借文本**：入库的是机制，不是可复用句子；单条引用 ≤3 句并标出处。
2. **不复述剧情当分析**：每一栏都要回答"为什么"。
3. **每回必须有反事实**：答不出"删掉会怎样"，说明这栏没想清。
4. **不编造**：文本缺失/OCR 残缺处写概括，不猜补；不确定的细节宁可不写。
5. **区分"我喜欢"与"它有效"**：个人口味写进备注，不混进机制结论。

## 七、验收清单（每批必过）

| # | 检查 | 通过标准 |
|---|---|---|
| 1 | 回数 | 每批 = 10，回号连续 |
| 2 | 卡片 | 每回 7 栏齐全，`章主题` 行存在 |
| 3 | 反事实 | 每回 1 条 |
| 4 | 编号 | 只在本批区间，无跨批撞号 |
| 5 | 引用 | 无 OCR 噪声句，单条 ≤3 句，**且过 ③B 引文回源（`check_quotes.py` 退出码 0/3）** |
| 6 | 缺陷 | 源文件问题已登记并在报告顶部警示 |

```bash
# 快速自检
grep -c '^### 第' <报告>          # 应为 10
grep -c '| \*\*章主题\*\* |' <报告>  # 应为 10
grep -c '\*\*反事实\*\*' <报告>     # 应为 10
```

## 八、实战教训（《红楼梦》120 回）

| 坑 | 现象 | 对策 |
|---|---|---|
| 回目误判 | 切出 121 章 | `第X回` 后必须跟分隔符 |
| 简写回目 | 文件名多一个「回」 | 剥 `^[回章节]\s*` |
| 第 55 回截断 | 字数正常，读到一半发现接续书 | 分析前抽读首尾 + 缺陷登记 |
| 第 3/120 回重复 | 字数偏高 | `chapter_health.py` 查重复段 |
| 引号配对误报 | 38 章误报 | **不做**引号配对检查（本书跨段引号多） |
| 并行撞号 | 多份报告同 ID | 分派时预设编号区间 |
| 后期打法过多 | P-01~P-177 太散 | **全书读完再合并**成 30~40 条常用打法，不要边读边回填 |
