# 好小说拆解库（正面样本 · 可迁移做法）

> **这份文件补的是三个真实的洞**：
> 1. **规则全是"不要什么"，没有"好是什么"**——`anti-ai-rules.md` 六门 + T1/T2/T3、`style-rules.md` 禁用清单，全是负向约束。只告诉 AI 别踩坑，它不会因此写出好句子。
> 2. **`自查报告模板` 里写着"通过 → 写进规则库作为正面样本"，但那个"规则库"此前根本不存在**——通过项无处可去，正面经验留不下来。
> 3. **`anti-ai-rules.md` 的"报警线"一直空着**（标注"待补——需人类样本"）。没有人类样本，所有阈值只能拿本项目的 3.6 自乘 1.25，是"比自己好一点"，不是"人类上限"，防误杀能力为零。
>
> **定位**：与 `anti-ai-rules.md`（负向）、`style-rules.md`（文风）、`craft-toolkit.md`（结构工具）并列的**正向样本库**。只借**结构与方法**，不借文本。

---

## 一、使用纪律（先看这条，否则会变成抄句子）

1. **借结构不借文本**：入库的是"这一段为什么有效 + 可迁移的做法"，不是可以复用的句子。
2. **单条引用 ≤3 句**，且必须标注出处；长篇原文不入库，只留定位（书名 + 章节 + 大致位置）。
3. **不抄情节**：可以学"用空间写阶级"，不能学"主角也在酒店当伙计"。
4. **样本要能被证伪**：每条拆解必须写出"如果删掉这一句/换一种写法，效果差在哪"。
5. **入库前先过 `anti-ai-rules.md` 三条硬边界**：信息守恒 / 最小改动 / 结构不动。

## 二、拆解卡（每个样本填一张，7 个观察位）

| # | 观察位 | 追问 | 记什么 |
|---|---|---|---|
| 1 | **这一句在干什么** | 删掉它，读者会缺什么信息或什么感觉？ | 功能：交代 / 推进 / 施压 / 喘息 / 转折 / 收束 |
| 2 | **信息怎么给** | 是直说、动作带出，还是让人物说错话露出来？ | 给法：直述 / 动作 / 对白 / 物件 / 留白 |
| 3 | **情绪落在哪** | 作者写"情绪"了吗？还是只写了可看见的东西？ | 落点：手 / 眼 / 呼吸 / 物件 / 空间 |
| 4 | **节奏** | 句子长短怎么变？哪一句突然变短？ | 长短交替 / 断句位置 / 段落切分 |
| 5 | **视角与距离** | 摄影机在哪？贴着谁？ | 贴身 / 旁观 / 全知（越全知越假） |
| 6 | **钩子或回响** | 这一段结束时，读者多知道了什么、又多怕了什么？ | 新信息 / 新威胁 / 新疑问 |
| 7 | **可迁移的做法** | 换成我的题材，能怎么用？ | 一句可执行的操作，不是"要写得真实"这种空话 |

## 三、已入库样本

### 样本 1 · 环境锚点：把"去办事"写成"进了一个世界"

**来源**：本项目真实改稿对照（`style-rules.md` 同款，林北线），非外部作品。

**改前**（一句带过）：
> 他把那张纸折好，揣进外套内袋，坐班车去了联合指挥部。

**改后**（同一件事，三段）：
> 他把那张纸折成四折，揣进外套内袋，出门拦了一辆去城东的班车。班车是铁皮敞篷的，一路都在抖，风里裹着工地的灰，落在嘴里发涩。到站时他拍了拍肩，肩上落了一层白粉。
> 联指的楼是三层灰楼，台阶被踩得发亮。大厅里冷气开到十几度，他一进门打了个激灵，低头看了一眼自己那双沾了机油的靴子，往里收了半步。

**拆解**：

| 观察位 | 结论 |
|---|---|
| 在干什么 | 不是交代交通，是**用路程把"底层"与"机关"两个世界接上** |
| 信息怎么给 | 全用可感细节（铁皮抖、灰发涩、台阶发亮、冷气打激灵），**没有一句"他很卑微"** |
| 情绪落在哪 | 落在**肩上白粉**和**往里收的半步**——身体替他说了身份差 |
| 节奏 | "折成四折"比"折好"多一个动作；三句一顿，段落短 |
| 视角 | 贴身跟着主角，只写他能感到的（嘴里的涩、肩上的粉） |
| 回响 | 进门先看自己的靴子——**读者已经知道他在这栋楼里没有位置** |
| 可迁移 | 换场景时问三句：**温度差？光从哪来？身上带了什么不该带的？** 三选二即可 |

> **反证**：若只写"他到了联指，心里有些自卑"，信息一样，画面为零，且犯了 C 门（心理直述）。

### 样本 2 · 一句话写死身份矛盾

**来源**：鲁迅《孔乙己》（公版）。原文一句：
> 孔乙己是站着喝酒而穿长衫的唯一的人。

**拆解**：

| 观察位 | 结论 |
|---|---|
| 在干什么 | 一句话同时交代**经济地位**（站着喝＝短衣帮）与**自我认同**（穿长衫＝读书人） |
| 信息怎么给 | 不解释，把两个**互斥符号**并置，矛盾自己说话 |
| 情绪落在哪 | 不在情绪，在**衣服与姿势**这两个可见物上 |
| 节奏 | 全句 17 字，一个"而"字承担全部张力 |
| 视角 | 旁观者概述，冷，不评判 |
| 回响 | 读者立刻明白：这个人**既不属于这边，也不被那边接纳** |
| 可迁移 | 给角色找**两个互斥的可见符号**（穿什么 / 站哪 / 用什么 / 跟谁一起），并置，不解释 |

> **反证**：若写成"孔乙己是个穷困潦倒却自命清高的读书人"，是**评价**，不是**呈现**——读者只能接受，不能看见。

### 样本 3 · 技术流爽点：爽在"可验证"，不在"嗓门大"

**来源**：本项目方法论（`style-rules.md` 技术流爽点），结构概述，不引原文。

**结构**：
> 外行/权威下结论 → 主角指出真正的病根（给出可验证细节）→ 对方不信 → 实测打脸 → 主角给出别人给不了的方案。

**拆解**：

| 观察位 | 结论 |
|---|---|
| 在干什么 | 五步里**三步都在"给证据"**，只有一步是"打脸" |
| 信息怎么给 | 靠零件名、读数、公差、流程顺序——**细节本身就是权力** |
| 情绪落在哪 | 不写"他很爽"，写对方的**动作变化**（伸手去摸、声音低下去） |
| 节奏 | 结论句短，证据句长；打脸句最短 |
| 视角 | 贴着主角的手，不贴对手的脸 |
| 回响 | 读者学到了一点真东西——**这是技术流和吵架文的分水岭** |
| 可迁移 | 写爽点前先问：**我能不能给出一个读者可验证的细节？** 给不出，就还是吵架 |

## 四、待填样本槽位（需要真实好文本）

> 下面这些**必须由作者提供原文**才能入库——我不能凭空分析不存在的文本，网文段落也有版权。你给章节，我按上面的拆解卡填。

| 槽位 | 要什么 | 用来补哪个洞 |
|---|---|---|
| A · 网文开篇 3 章 | 你认为"一上来就抓人"的 3 章（同平台同题材最好） | 开篇钩子 / 信息释放速度 |
| B · 网文对话张力段 | 1 段"两个人互相试探"的对白 | E 门（对话）目前只有负向规则 |
| C · 网文爽点段 | 1 段"打脸/逆袭"高光 | 爽点结构只有抽象五步 |
| D · 网文日常/喘息段 | 1 段"没大事但好看"的过渡章 | 防"章章高强度"（认知过山车） |
| E · 公版白描段 | 鲁迅/老舍等公版作品 1 段 | 白描与环境的标杆 |

**投喂方式**：直接给文件路径或贴文本 + 一句"我要它的哪一点"（这一句最关键，决定了拆解往哪个方向做）。

## 五、报警线校准表（★ 这份库的第二个用途）

`anti-ai-rules.md` 的报警线 = **同类人类作品上限 × 1.25**。**不再手填**——用脚本算：

```bash
# 1. 把槽位 A~D 的样本（人类写的、你认可的）放同一目录
# 2. 一条命令算出上限与报警线（复用 lint_prose 的 analyse 口径，不另算一套）
python scripts/calibrate.py <样本目录> --out 报警线.md --json 报警线.json
# 3. 把产物 报警线.md 整段贴回 anti-ai-rules.md 的「两条线要分清」
```

- 退出码：`0` 已产出 / `2` 无可分析样本 / `3` 有样本被跳过（校准值可能偏低）。
- **越低越好**的指标（AI味、破折号）取 (上限×1.25 / 上限+1 / 目标线) 三者最松——人样 T1 常为 0，`0×1.25` 仍是 0，会把正常写法全报掉。
- 换题材/换平台**必须重新取样本**：不同题材的合理密度不同，一套阈值不能走天下。

| 指标 | 人类样本上限 | ×1.25 = 报警线 | 当前目标线 | 校准状态 |
|---|---|---|---|---|
| 神态/千字 | | | 4.5 | ⬜ 待样本 |
| 环境段% | | | ≥22 | ⬜ 待样本 |
| 对话密度% | | | — | ⬜ 待样本 |
| AI 味/千字 | | | ≤1.5 | ⬜ 待样本 |
| 破折号/章 | | | ≤3 | ⬜ 待样本 |

> **没有这张表**：所有阈值都是"比现在的自己好 25%"，不是"人类也这么写，你凭什么报警"。
> **有了这张表**：`lint_prose` 的报警才有防误杀能力，`analyze_arc` 的连续同向判断才有外部锚。

## 六、打法清单（可被 ④ 章纲直接引用）

> **为什么要有编号**：没有编号，"参考好样本"就是一句空话；有了编号，④ 章纲必须写 `P-03`，⑥ 复查才能反查"你说要用 P-03，用了吗"。
> 每章**至少标 1 个**；标了就必须在正文里找到对应做法，否则 ⑥ 判为"承诺未兑现"。

| ID | 打法 | 一句操作 | 适用场景 | 来源 |
|---|---|---|---|---|
| **P-01** | 环境锚点三选二 | 温度差 / 光源 / 声音 / 气味质地，选两个写，≤3 句 | 每场戏开头、场景转换 | 样本 1 |
| **P-02** | 互斥符号写身份 | 找两个互相矛盾的可见符号并置，不解释 | 角色首次登场、身份揭示 | 样本 2 |
| **P-03** | 情绪落手 | 不写"他紧张"，写手在干什么（换手/蹭裤缝/停住） | 所有压力场面 | 样本 1、3 |
| **P-04** | 爽点五步 | 权威下结论 → 主角给病根 → 不信 → 实测打脸 → 给方案 | 技术流爽点章 | 样本 3 |
| **P-05** | 信息钩 | 章末抛一个改变判断的新信息，不解释 | 章末（与抉择/代价钩轮换） | `style-rules.md` |
| **P-06** | 场景切换双锚 | `——` 独立成行 + 新场景第一个锚点 | 换时间/换地点 | `style-rules.md` |
| **P-07** | 对白动作节拍 | 每 2~3 句对白插一个身体动作，防"他说/她看他" | 长对话段 | 样本 1 |
| **P-08** | 物件承载信息 | 让一个物件（划痕/纸角/白粉）替人物说状态 | 需要"少说多做"的段落 | 样本 1、2 |
| **P-09** | 冷叙述 | 视角贴身，只写看见听见的，不评判、不升华 | 全篇默认 | 样本 2 |
| **P-10** | 回填六项 | 环境→动作节拍→技术细节→追问回合→内心吐槽→配角反应 | 字数不足时按序补 | `style-rules.md` |

> 新增打法：填一张拆解卡 → 提炼成上表一行 → **立刻给它编号**。没编号的打法不算入库。

## 七、和主流程的接线

- **④ 章纲（强制）**：每章必须标 ≥1 个 `P-xx`（第六节）；纯过渡章写 `P-00` 并注明理由。**标了但正文没用 = 承诺未兑现，⑥ 判硬伤。**
- **⑥ 复查 · 通过项**：`自查报告` 的"通过"不再是一句夸奖，而是**填一张拆解卡**，存进本库第三节。
- **⑥ 复查 · 失败项**：改法必须**引用具体打法编号**（"按 P-03 把'他很紧张'改成手部动作"），不许写"补描写"这种空话。
- **入口 D（样本拆解支线）**：入库流程见 `pipeline-stages.md`「入口 D」——选样定焦 → 跑脚本 → 拆解卡 → 编号入库，一道门。
- **② 梗概**：找结构参考时先看 `三幕十五节拍表.md`，再看本库的"可迁移做法"列。
- **`anti-ai-rules.md`**：报警线一律以 `scripts/calibrate.py` 的产物为准，不再手填。
- **`style-rules.md`**：本库样本 1 就是它的同款对照，新增文风规则时从这里取正例。
