### 1.1 作者的意见（原话）

| # | 日期 | 位置 | **原话** | 类型 |
|---|---|---|---|---|
| 1 | | | | 文字／一致性／结构／流程 |

> **不许转述**。原话才是判断"这条规则该定多严"的唯一依据。
> 例：作者说「这个—— 是什么意思，要改的」——原话里带着"不懂、觉得怪"；转述成"用户不喜欢分隔符"就丢了关键，
> 会导致错误处理（直接删掉），而正确反应是"解释 + 给选项"。

## 四、提炼出的规则（★ 核心）

> 逐条问：**这条能不能防止下次再犯？** 能 → 按归属归类；不能 → 只留在项目问题本。

| # | 规则一句话 | 归属 | 落到哪 | 状态 |
|---|---|---|---|---|
| 1 | | **可检测** → 脚本 | | 待落地／已落地 |
| 2 | | **要判断** → 提示词 | | 待落地／已落地 |
| 3 | | **是步骤** → 流程 | | 待落地／已落地 |

**归属判定标准**：

| 特征 | 归属 | 理由 |
|---|---|---|
| 能数出来（密度、计数、配对、比例） | **脚本** | 客观、可复现、能当卡点（退出码） |
| 要判断（像不像念台词、伏笔该不该收） | **提示词** | 机器判不了，但可约束 AI 必须引用原句 |
| 是步骤（先做什么后做什么） | **流程** | 顺序错了，后面的活白干 |
